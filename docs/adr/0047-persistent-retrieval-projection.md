# 持久检索投影与排序：按目录版本刷新，服务端发现歧义

目录搜索（ADR-0041）现在按命中的词数打分：别名不优先，同名不同口径的指标分不出来，也不按分析主题或空间加权。同名指标在不同分析主题、不同空间里口径不同（ADR-0046、ADR-0048），需要把每个条目的检索文本、作用域、别名与向量存下来，才能快速检索。决定：**部分修订 ADR-0041**。「不存成文档」约束的是权威事实：映射、定义、实体、权限仍然每次按当前元数据实时读，不另存副本。可以重建、标明来源版本的检索投影允许持久化，它不是第二份事实。

**按性质决定存不存。**

| 性质 | 例子 | 处理 |
|---|---|---|
| 权威事实 | 映射、DSL、实体、权限 | 实时读，不存副本 |
| 人的知识 | 别名、口径声明、主题、提案（ADR-0046） | 持久保存，属于权威元数据 |
| 昂贵的计算 | embedding | 按 `(租户, 模型, 文本哈希)` 缓存，丢了可以重算，不参与权限判断 |
| 派生投影 | 每个条目的检索文本、作用域（主题、空间）、别名 | 持久保存，记下是按哪个目录版本建的，随时可以从头重建 |

**按目录版本刷新，不建 outbox。** 目录版本本来就是一条持久的变更日志：成员操作时在同一事务里比较并记下版本与差异，采集、同步后也会补记（ADR-0041）。投影记下自己的目录版本，检索时发现落后，就按 `catalogChangesSince` 的差异增量刷新：差异小在请求里同步做，差异大交给现有调度器的持久任务。embedding 由调度器异步补算，没算完的条目暂时只走关键词与别名检索。没有选「新建 outbox 表 + 独立 worker 进程」：那是第二条变更日志，每个新的元数据写入点都要记得补发事件，否则就漏，还要定期对账；而且要多部署一个进程。以后实测到刷新拖慢请求，或者需要把变更实时推给别的系统，再改成 outbox。

**可见性类别跟着 `catalogFor` 走。** 投影按 `catalogFor` 实际用来裁剪目录的权限位组合分类，目前只有一个权限位（`sources:read`），所以是两类。每类从已经裁剪过的目录生成自己的检索文本与向量，所以检索看到的和按标识展开看到的永远一致。查询哪一类由服务端按成员的权限算出来，工具入参不能指定。空间是查询时的过滤和加权条件，不再增加类别。`catalogFor` 以后多一个裁剪维度，类别跟着增加。

**排序。** 多路召回：精确标识、名称与别名、中文关键词（沿用二元组），配置了 embedding 时再加向量（ADR-0049）。用按排名融合（RRF）合并，不直接把各路分数相加，权重由黄金集定。别名命中优先于正文命中。

**作用域只加权，不排除。** 优先级从高到低：成员这次明确说的（永远不被覆盖）、页面上下文、这段对话里已经确定的主题或口径、成员所属空间。别的主题的同名定义照样留在候选里；只有得分明显拉开（阈值由黄金集定）并且口径声明一致时，才能不追问直接选。

**歧义由服务端发现。** 几个候选共享同一个别名或名称、口径又不同时，`catalog_search` 标记 `ambiguous`，并返回结构化的口径对比：分子与分母、窗口、时间字段、粒度、口径声明的差异。追问的问题由这些差异生成（比如时间字段不同就问「按哪个时间算」）。工具描述和 `validate_plan`（ADR-0050）都要求先问清楚再继续。不交给提示词让模型自己判断，因为「同名不同口径」正是这次要保证正确的地方。

## Consequences

- 别名命中、作用域加权、歧义判定都是确定性的，用普通的 vitest 测，进 CI；模型那一层由 `pnpm eval:requirements` 评测，不进 CI。
- 新排序替换 `search()` 后，`catalog_search` 的输入不变，输出多出命中理由与 `ambiguous`。
