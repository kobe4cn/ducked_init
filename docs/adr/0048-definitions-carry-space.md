# 定义记下所属空间，但还不按空间隔离

空间（CONTEXT.md）是租户内的数据归属单元，比如品牌或事业部。可是 `space_id` 现在只在创建数据源和映射时记下当前空间（`sources.ts`、`mappings.ts`），没有任何地方按空间读取、过滤或检查权限。成员不属于某个空间，每个租户只有一个默认空间，标准层也是全租户一份。指标、标签与模板定义（`dsl_definitions`）连 `space_id` 都没有。

同名指标在不同事业部口径不同（ADR-0047），检索需要知道定义属于哪个空间。决定：**定义加 `space_id`，和数据源一样记为当前空间；检索投影带上空间，用来加权和过滤。不做按空间的隔离。**

没有一次做完整的多空间（成员分配到空间、按空间控制权限、计算只读本空间的数据），是因为那要改映射、合并、身份打通、服务库与权限这一整条链，工作量和风险都远超检索本身。完整的多空间作为独立项目，另写 ADR。在那之前，同一租户里同名不同口径的区分主要靠分析主题（ADR-0046）。

## Consequences

- 已有的定义迁移时归入租户的默认空间。
- 空间现在不是安全边界：不能因为定义带了 `space_id`，就以为其他空间的成员看不到它。
