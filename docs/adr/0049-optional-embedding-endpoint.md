# embedding 端点：可选配置，与 chat 同一套规则

混合检索（ADR-0047）可以加一路向量召回，但模型服务客户端（ADR-0035）现在只有 chat（`chatJson` / `chatTools`）。chat 端点未必支持 embedding，embedding 也不该用聊天模型代替。决定：

**可选的 embedding 配置。** `model_providers` 加一组可选的 embedding 端点、模型与 Key。规则和 chat 一样：平台默认取环境变量，租户填了就整套覆盖、不混用；租户 Key 按租户信封加密（ADR-0009）。embedding 和 chat 可以指向不同的服务。都没配置时不报错，检索只走关键词与别名，其余功能照常。

**不需要新的外发政策。** 发给 embedding 的只有可见性投影里的检索文本（ADR-0047），也就是本来就会作为语义目录发给 chat 的元数据，不含明细行、结果、凭据或敏感字段。所以沿用 chat 的外发边界，不另加开关或端点白名单。

**和 chat 一起记录。** `llm.ts` 加 embed 适配，和 chat 走同一套超时与调用记录（用途、模型、条数、用量、耗时），不记请求原文。

**换模型就重建。** 向量缓存的键里含模型标识，换模型（即使维度相同）就命中不了旧缓存，由调度器在后台按新模型重算，算完前那部分条目只走关键词检索。

## Consequences

- embedding 是否默认启用，由黄金集上 Recall@20 的开关对比决定。
- 端点超时或失败时，向量这一路降级关闭，不影响检索的其余部分。
