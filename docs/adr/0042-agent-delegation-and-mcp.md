# 代理授权：平台外的 Agent 凭成员个人令牌经 MCP 接入

客户想用自己的 Agent（如 Claude Code）读语义目录（ADR-0041）、起草定义与查询。API Key 的调用方是「系统」（ADR-0040），不代表任何成员，也没有权限范围：用它起草，草稿没有作者，双人发布也就失去依据；而且给营销系统用的 Key 也能看到全部结构。决定：Agent 代表一位成员接入，凭**成员个人令牌**（成员自己签发，有效期可选、可吊销，平台只存哈希，只在签发时显示一次），访问挂在同一应用 `/mcp` 的 MCP 服务（Streamable HTTP）。完整的 MCP OAuth 流程以后再做。

- 能做的事等于这位成员的权限，草稿记在这位成员名下，审计注明经 Agent。**Agent 永远不能发布**，发布照旧由人在页面上双人确认。「注明经 Agent」落在审计 detail 的 `via` 上（平台内助手为 `'assistant'`，以后 MCP 为 `'mcp'`），只加在 Agent 调用工具时用的成员身份上、不写进会话；detail 不记需求原文与 YAML。
- 起草时先校验再保存；校验或保存不通过时把问题清单回填给模型，最多再修正 3 次，仍不通过就不保存，把问题清单与最后一版 YAML 交给成员。
- 平台内的 AI 助手与 MCP 共用一张工具注册表（名称、输入输出 Schema、所需权限、是否允许外部调用），外部能用的始终是内部的子集。
- **平台内助手先看工具调用探测结果。** 模型服务页「测试连通性」时带一个 ping 工具探测一次，结果连同当时生效的端点与模型按租户存在 `model_providers` 上；端点、模型变了（包括恢复平台默认、平台默认换了模型）就作废。只有明确的结果才存：返回了工具调用算支持，模型服务拒绝带工具的请求（4xx，不含 429）算不支持；只回了文本（`tool_choice: auto` 下支持的模型也可能不调用）和超时、连不上、5xx、429 都算没能确认，不存、也不覆盖上一次的结果。存的是「不支持」时助手不发请求、直接提示；没探测过或没能确认时照常可用，出错走 422。误判「不支持」会停掉整个租户的助手，所以宁可不存。
- **执行查询要单独勾选。** 外部 Agent 背后的模型由客户选择，平台管不到数据流向，所以执行工作台查询（规则同 ADR-0036，结果剔除敏感列与哈希列）只在成员签发令牌时勾选「允许执行查询」后才能用，每次记审计。

## Considered Options

- 复用 API Key：没有成员身份，权限过大，否决。
- 单独建一种「Agent 身份」并配权限：要再维护一套权限，且草稿仍然没有对应的人，否决。
