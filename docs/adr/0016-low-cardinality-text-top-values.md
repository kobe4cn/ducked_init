# 列统计保存低基数、不像敏感信息的文本列的常见取值

列统计原先对文本列只记录长度范围与格式特征，不保存任何取值：取值可能就是手机号、邮箱、姓名，而列统计存在平台 PG 的任务结果里（`tasks.result->'tables'`），不在租户数据湖中，也不受 ADR-0005 的加密与哈希保护。

但映射草稿要把源端的枚举值（订单状态、渠道、城市）对到标准模型的值字典（ADR-0015），对照面板和按规则生成草稿都需要知道源端到底有哪些取值。只给长度和格式时，成员只能另开工具去源库查，规则也无从生成。

现在放宽为：采集列统计时，满足以下全部条件的文本列（`VARCHAR`）在 `ColumnProfile.top` 里保存样本中最常见的取值与各自的样本行数，按行数从多到少，最多 50 个。
- 样本中不同取值（近似）不超过 50。
- 列名不像敏感信息：不命中 `phone`/`mobile`/`tel`/`mail`/`name`/`addr`/`id_card`/`id_no`/`passport`/`cert`/`birth`/`ssn`/`contact` 等英文片段，也不命中“手机、电话、邮箱、姓名、名字、地址、身份证、证件、生日”等中文（完整清单见 `app/lib/sensitive.ts` 的 `SENSITIVE_NAME`）。
- 样本中**没有任何一个**取值符合邮箱或手机号格式（不是格式特征里“至少一半符合”的门槛：混着少数手机号的备用联系方式列也排除）。
- 最长的取值不超过 64 个字符：更长的多半是备注之类的自由文本。

不变的部分：
- 文本列的 `min`/`max` 仍然为空，取值只出现在 `top` 里。
- 只采集同步范围内的表（ADR-0013），范围外的表的取值不会进入任务结果。
- 空值不计入常见取值，空值比例照旧在 `nullRate` 里。

## 已接受的取舍

- 判断“不像敏感信息”靠列名与格式，是启发式的：列名不规范、取值又不是手机号邮箱格式的低基数敏感列（例如名为 `c3` 的会员等级备注里写了人名）仍可能被保存。基数上限 50 让这种泄露的范围很小，且只对本租户可见；需要时再加按数据源的排除名单。
- 规则偏保守：`product_name`、`hotel_type` 之类列名会被误排除，看不到取值。宁可少给。

## Considered Options

- 继续不保存任何取值：隐私最稳，但值字典映射只能靠成员手工去源库查。否决。
- 取值哈希后保存：对照与生成规则需要明文取值，哈希没有用。否决。
- 只对成员手动标为“可展示”的列保存：最可控，但每张表都要多一步操作，接入向导变重。暂不采用，可作为日后补充的排除 / 放行名单。
