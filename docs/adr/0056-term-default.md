# 词的默认指向：成员给歧义词定一个默认条目，免一次追问（修订 ADR-0047 的追问规则）

同名不同口径的指标在检索时由服务端判歧义、生成追问（ADR-0047）。多数租户其实有固定答案：「营收」在这家租户永远指近一年营收，问过一次之后就不该再问。决定：**新增一种业务知识「词的默认指向」（提案种类 `term_default`），成员在 `/knowledge` 审核接受后生效，回答按它免追问**。本票只做存储、提案与接受；歧义判定怎么用它由下一张票接。

**①一个词同一时间最多一个有效默认。** 新表 `knowledge_term_defaults`：`(租户, lower(term))` 在未停用的行里唯一（部分唯一索引，`retired_at is null`）。只加和停用、不改值：接受指向新条目的提案就把同词旧的停用（`retired_at`），停用的行留档；审计 `term_default.set` 的 detail 记 `replaced`（旧目标的 targetId）。并发下靠唯一索引兜底：撞 23505 改写成 400、整个接受回滚，提案留在待确认，重试即可（与别名同做法）。

**②生效条件与别名、口径声明都不同。** 提案接受后才生效（ADR-0046 的提案-接受流程，AI 只能提案）；默认条目的依据摘要（`basedOn`，与别名同口径）变了时**不生效、照常追问**——直接不加载，不列为待复核。理由：别名照常生效标「待复核」、口径声明复核前按「未知」，都是「内容还在、提醒人看」；默认指向的价值就是免追问，指向一个定义已变的条目还自动生效，比追问一次更糟，所以过期的默认干脆不参与。

**③优先级：查询里点名的维度 / 口径 > 默认指向 > 追问。** 成员明确说的永远不被覆盖（ADR-0047）：点名把默认条目排除了，就按点名处理；点名没排除它、或者没点名，才用默认指向替掉追问。

**④按默认作答要写明。** 回答开头写「按默认口径 X 理解『词』」，让成员有机会纠正——沉默地替人选择口径，出错了最难发现。

**⑤来源是对话里成员的选择，不是用户原话。** 提案由助手对话中的成员选择产生（ADR-0046 入口 ⑥），content 只有 `term` 一个词，证据只记引用（evidence ref），不存用户原话。词本身必须是目标条目**当前的名称**（指标 / 标签的 key、实体的 label、字段的 label 或 name，与 `buildCatalog` 同口径）或**有效别名**，不分大小写；不是就 400。目标改名或别名停用后，指向不因此删，但条目不在目录里时自然加载不到。没有「修改后接受」：改值就是换目标，那是另一条提案。

存储与记账沿用现有机制：挂在目标条目的 `knowledge` 上（`termDefaults`，参与目录快照与检索文本），接受在 `catalogTx` 里审计 `term_default.set`、记目录版本 +1（ADR-0054）；查看者不能接受（403，同其他提案）。

## Consequences

- `knowledge_term_defaults` 表与迁移；`term_default` 进 `ProposalKind`，面板与 `/knowledge` 显示「『词』默认指这一条」，只有接受与拒绝。
- 歧义判定（ADR-0047 的 `ambiguous`）在下一张票改为：有有效默认指向时不再 `ambiguous`，按 ③④ 作答。
