# 映射以表单为主要编辑方式，YAML 仍是唯一的数据与存档格式

ADR-0015 让成员直接编写映射 YAML：`fields` 只能写标准字段、租户特有字段写在 `extensions` 里且带 `type`、表达式只能用白名单函数、枚举用 `dictionary` 对应。规则本身合理，但要先学会这套写法才能动手。实际使用中，连数据工程师也要边查文档边写，常见的错误（把标准模型已有的下单时间写成 `x_order_ts` 放在 `fields` 下）只换来一条看不懂的报错。懂业务、不懂技术的人基本写不出来。

现在决定：
- 映射页以**表单**为主：每个标准字段选一个源列，配常用转换（单位换算、转文本、时区转换、日期解析、拼接、固定值）；枚举字段展开成「源值 → 标准值」对照表，并选一个兜底；扩展字段勾选源列，类型按列统计带出。表单的文案用业务语言，函数包装成选项。
- **YAML 是唯一的数据**：表单读 YAML、改 YAML（用 `yaml` 包的 Document API，保留注释与顺序），版本、校验、双人发布、合并都不变（ADR-0015）。YAML 作为「高级」标签页一直可用，与表单随时切换。
- 表单表达不了的写法有两层兜底：单个字段可以选「自定义表达式」直接写表达式；YAML 里有表单不认识的内容时，表单把那一项显示为只读，提示到 YAML 里改，切换时不丢内容。
- 新建映射默认从**按规则生成的草稿**开始（列名规范化与同义词匹配、类型与格式特征校验、值字典按常见取值预填，每条对应写明依据），人只做确认与修改。先只用确定性的规则，不调用模型，也不从历史映射里学。
- 起草权限不变：仍是有 `sources:write` 的数据工程师与管理员。表单按不懂技术的人也能用来设计，日后要开放给运营或实施人员时只需调整权限。

## 已接受的取舍

- 表单与 YAML 双向同步要多写一层，并要保证往返不丢注释、不打乱顺序；换来的是只有一份数据、一套校验与发布流程。
- 常用转换只覆盖常见情况，其余落到自定义表达式，那里仍需要懂表达式语法。
- YAML 编辑器的代码提示（#36）降为以后再做，只保留输入时的实时校验，表单和 YAML 都用得上。

## Considered Options

- 继续以 YAML 为主，只加生成草稿、对照面板、写法速查与更好的报错：改动小，但不会写 YAML 的人仍然写不了。否决。
- 只用表单，去掉 YAML：版本对比、审核发布依赖 YAML 文本，复杂情况也没有退路。否决。
- 表单另存一份结构化数据，发布时再生成 YAML：两份数据会不一致。否决。
