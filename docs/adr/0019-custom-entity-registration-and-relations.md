# 标准模型只收平台模板要用的实体，其余数据登记为自定义实体，用关系与维度路径接进指标、标签与模板

租户的数据五花八门：渠道表、区域表、门店、导购、活动、兑换单、工单……标准模型覆盖不了。ADR-0018 把积分、同意、优惠券升格成了标准实体，但如果每见到一种数据就升格一种，标准模型永无止境，也谈不上标准。现在这类表能进原始层（只看同步范围，ADR-0013），也能写成自定义实体（`custom_` 开头，ADR-0015）进标准层，但缺三样东西：自定义实体没有独立的定义（结构由各个映射拼出来）；CONTEXT.md 规定「所有指标与标签只基于标准模型」，进了湖也算不了；没有办法表达「订单的门店属于哪个区域」这种维度关系，`order.channel`、`order.store_id`、`customer.city` 都只是孤立的字符串。指标 DSL（#17）还没开工，现在定下来不会返工。

**分工。** 标准模型只收**平台模板必须依赖**的实体；升格的门槛是「有平台模板需要它」，不是「有租户有这种数据」。其余数据一律由租户登记为自定义实体，平台不为某一类数据（渠道、区域、门店）单独建实体。平台模板只依赖标准实体，但可以通过维度路径用到任何租户的自定义实体（见下）。租户自己的指标与标签可以引用标准实体、`x_` 扩展字段和已登记的自定义实体。

**实体登记。** 自定义实体先登记再映射。登记包含：名称（`custom_` 开头）、中文名、类型（维度或事实）、字段（名称、类型、说明、是否敏感）、主键，以及从它出发的关系。映射对照登记校验：自定义实体与字段必须登记过，类型按登记的来；引用没登记的实体或字段时，校验报错并给出 YAML 里的行列。类型只用于界面引导与草稿默认值（维度默认生成恒等映射，事实提示声明到 `customer` 的关系），不限制用法：维度也能作为指标的基础实体（如「各区域有多少门店」），事实也能出现在维度路径上。

**一键直通。** 维度表大多不需要转换。成员选一张源表，平台生成一组草稿：实体登记（字段与类型取自源表，主键取源表主键或业务主键，像敏感信息的列按 ADR-0016 的规则默认标为敏感）加一份恒等映射（全部列、去重键为主键）。这组草稿一起审、一起双人发布，不免审：敏感标记最后要由一个人确认（ADR-0005）。

**登记的生命周期。** 与映射同一套流程：草稿加双人发布（ADR-0015 的规则，发布者不能是最后保存草稿的人），起草需要 `sources:write`。发布后只允许新增字段与关系，规则与标准模型的兼容规则（ADR-0018）一致；改主键、改字段类型、改名要新建实体。被已发布的映射、指标、标签引用的实体、字段与关系不能删除。

**关系。** 关系是通用外键：起点是任意实体（标准实体或自定义实体）的任意字段，包括 `x_` 扩展字段；终点必须是目标实体的主键，两端类型一致。例如 `order.store_id → custom_store.store_id`、`custom_store.region_id → custom_region.region_id`、`custom_redeem.customer_id → customer.customer_id`。关系属于实体，不属于某个映射：同一实体所有映射的行都按它关联，某个数据源的行没有这个字段时结果为「未关联」；两个系统编码冲突（同一个码指不同的门店）时在映射里用字段表达式对齐（如加前缀），关系本身不带数据源。标准实体之间的关系（订单明细 → 订单、订单 → 消费者等）由平台内置。设计时平台按列名相似与取值包含（起点列的常见取值，ADR-0016，都落在终点主键里）推荐关系，规则不够时由大语言模型起草（ADR-0003），都由人确认。

**终点主键在整个实体内唯一。** ADR-0015 的去重按映射各管各的，同一实体里主键可能跨映射重复；被关系指向时 join 会把行数放大、把金额算重。所以被关系指向的实体，合并时跨映射检查主键唯一，有重复就让合并失败，列出冲突的键与所在的映射；由成员在映射里处理（加前缀、去掉一边的映射）。不按优先级悄悄取一行。`customer` 例外：多个数据源里同一个人的归并是身份打通（#11）的事，到 `customer` 的关系与 `order.customer_id` 一样指向源端的 `customer_id`，由 #11 统一解决到统一消费者的对应；#11 落地前，`customer` 不能作为维度路径上的一站。补充（#76）：统一消费者的对应关系落在 `silver._identities(_source, customer_id, consumer_id)`，每次合并到标准层之后由 `silver.customer` 整表重算；键是 `(_source, customer_id)`（`customer_id` 只在一个数据源内唯一）。`order.customer_id` 与自定义实体指向 `customer` 的关系，都带上行所在的数据源经这张表 join 到 `consumer_id`。维度路径按这张表走到 `customer` 之前，上面「不能作为维度路径上的一站」仍然成立。补充（#77）：匿名设备的归属落在 `silver._device_owner(device_id, consumer_id, login_at)`，与 `silver._identities` 同一个事务重算；口径是设备全局最近一次登录（`event_type = 'login'`，先写死），每台设备一行，并列按 `occurred_at DESC, consumer_id` 决定。`device_id` 不带 `_source`，跨数据源视为同一台设备（埋点通常只有一个源）；登录者在 `silver._identities` 里找不到的登录不参与。没有选「事件发生前的最近一次登录」，那需要逐事件归属、给事件补 `consumer_id`。

**维度路径。** 指标、标签与模板里的维度写成一条从基础实体出发的路径，例如 `order.store_id → custom_store.region_id → custom_region.name`。路径上每一步都必须是多对一（终点是主键），不成环，深度有上限。编译器在**计算时** join，用维度的当前值：门店调了大区，下次计算历史订单也算到新大区。关系里预留「按时间点关联」的选项，以后可以按原始层的变更批次（ADR-0006）取发生时的值，现在不实现。join 一律是左连接，找不到的键显示为「未关联」，不从结果里丢掉；平台在关系上统计孤儿比例给成员看，以后可以作为断言（#13）设阈值。

**平台模板怎么用。** 模板声明自己的基础实体（如 `customer`、`order`），把「切分维度」作为参数；租户启用模板时，可以选任意一条从基础实体出发的维度路径。模板本身不认识区域、门店。第一期只支持一条路径，多条路径交叉以后再做。

**指标不读原始层。** 原始层结构不稳定、敏感信息是明文（ADR-0005）、存的是变更批次而不是当前状态（ADR-0006）。所有数据都经映射进标准层后才能被指标引用；不需要转换的表靠一键直通把成本压低。

**敏感信息。** 自定义实体上标为敏感的字段，在标准层只存加盐哈希（ADR-0005）。敏感字段可以作为关系的键（两边都是同一种盐的哈希，仍能 join），但不能作为维度路径的终点：不能作为切分维度或报表输出。

**已有自定义实体怎么迁。** 上线时平台根据已发布映射为每个 `custom_xxx` 推断一份登记草稿（字段与类型取自扩展字段，主键取 `dedupe.key`，不推断关系），在映射页与实体页提示成员确认发布。确认前这些实体照常合并，但不能被指标、标签引用，也不能作为关系的起点或终点。

## 已接受的取舍

- 只按当前值关联：组织结构调整后，历史报表的口径会跟着变。多数 CRM 分析按当前组织看就够了；要按发生时的值，以后实现「按时间点关联」，原始层已经留有历史，不需要补数据。
- 终点主键跨映射唯一会让一些合并失败，成员要先在映射里处理冲突。换来的是维度切分不会悄悄算重。
- 一键直通仍要双人发布，接入一张维度表最少要两个人。成本主要在起草，已经自动化了。
- 第一期不做平台维护的登记模板（「门店」「区域层级」「导购」）：每个租户都从源表生成自己的登记。等观察到多个租户反复登记同一种结构再做，套用后仍是租户自己的实体，平台模板不能依赖它。
- 术语沿用「自定义实体」，与代码里的 `custom_` 前缀一一对应。

## Considered Options

- 每见到一类常见数据就升格为标准实体（门店、区域、渠道……）：永无止境，各租户的结构也不一样，定了字段多半要改。否决；升格只看平台模板需不需要。
- 不要标准模型，全部由租户定义、模板全部参数化：模板失去可依赖的结构，每个租户要先配很多东西才能出第一张报表。否决。
- 「可选标准实体」：租户启用后平台模板就能依赖。本质上又是一个标准模型，会把分工打乱。否决。
- 只做到 `customer` 的关联（#44 原来的设计）：渠道、区域这类维度挂在订单上，不在消费者上，解决不了问题。否决。
- 在映射或源视图里把维度属性压进事实表（订单行上直接带区域）：维度变化后，只有事实本身有变更批次的行才会重算，历史订单停在旧值。否决；维度在计算时 join。
- 跨映射主键重复时按映射优先级取一行，或者主键自动带上 `_source`：前者悄悄丢数据，后者把数据源这个技术概念带进业务关系。否决。
- 关系声明在映射级：同一条维度路径在不同行上含义不同，指标面对的是整个实体。否决。
- 允许指标直接读原始层：破坏 ADR-0005、0006 与 0015。否决。
- 结构继续从映射推断，不单独登记：主键、关系、敏感标记没有地方声明。否决。
