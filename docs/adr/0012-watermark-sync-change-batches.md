# 水位线增量同步：数据源与数据湖挂在同一个 DuckDB 里，批次日志随变更批次写进数据湖

对已确认水位线字段的表，平台每小时同步一次，把变化作为变更批次（ADR-0006）追加到原始层。工作进程在同一个 DuckDB 里先挂载本租户的数据湖，再以 `src` 只读挂载数据源（ADR-0009），然后锁住配置（ADR-0008）。这样数据可以直接从源端写进湖里，不经过本机文件。两边都在对象存储上时，两把 S3 凭据用 `SCOPE` 各自限定在自己的前缀上。

原始层按数据源分 schema：`bronze_<数据源 ID>`。每张源表对应一张原始层表，包含源表的全部列，再加四列：
- `_op`：新增或更新。
- `_commit_ts`：源端提交时间。
- `_batch`：批次号，每张表从 1 起递增。
- `_synced_at`：同步时间。

同一 schema 里还有一张 `_batches` 批次日志，记录每张表每个批次的方式、水位线起止和行数。它与变更批次在同一个 DuckLake 事务里写入，是下一次同步起点的唯一依据。这样即便调度器没来得及记下任务结果，下一次同步也会从湖里实际写入的位置继续，不会重复或跳过批次。成员在数据源页看到的同步历史来自 `source.sync` 任务的结果。

一次同步：
1. 读取这张表最近一个批次。如果它用的不是当前的水位线字段（首次同步，或成员换了字段），这次就全量读取；否则读取水位线**及之后**的行。PostgreSQL 与 MySQL 的条件写进经 `postgres_query` / `mysql_query` 发往源端的查询，在源端执行，不依赖扩展的条件下推。其他数据源在 DuckDB 里过滤（Parquet 可以按行组统计跳过数据）。
2. 用“大于等于”，是为了不漏掉与水位线同一时刻、但在上次同步之后才提交的行。上次已经同步过的边界行，按整行哈希识别后跳过。
3. 源表有主键时，原始层里已经有该主键的行记为更新，否则记为新增。MongoDB 以 `_id` 作主键。
4. 更新时间水位线的提交时间取该字段（不带时区的时间一律按 UTC 解读）。自增主键拿不到提交时间，用同步时间代替。
5. 源表新增的字段，在原始层随之加列。

同一数据源同时只有一个同步在排队或运行：入队前锁住数据源行，再检查已有的任务。常驻调度器每分钟检查一次到期的数据源，同步周期由 `SOURCE_SYNC_INTERVAL_MINUTES` 设定，默认 60 分钟。成员可以随时手动触发一次。每张表各用一个事务，一张表失败不影响其他表。有表失败时，任务记为失败，结果里保留各表的批次与错误。

## 已接受的取舍

- 水位线同步看不到源端的硬删除，本期只产出新增与更新。这偏离了 ADR-0006“水位线同步也必须显式产出删除记录”：删除记录改由每天比对主键全集的任务（另行实现）以同样的变更批次追加，或由映射里声明的软删除字段表达，标准层仍然只消费变更批次。自增主键水位线只能发现新增，发现不了修改（ADR-0011 对 ObjectId 也有同样的说明）。
- 水位线只能发现“提交时水位线字段已经大于等于上次水位线”的行。源端长事务在上次同步之后才提交、但更新时间早于水位线的行（PostgreSQL 的 `now()` 取事务开始时间），以及自增主键分配顺序与提交顺序不一致时晚提交的小主键，都会被漏掉，只能靠每天的主键全集比对补上。需要时可以加回看窗口（从水位线往前多读一段，按整行哈希去掉已同步的行）。
- 同一数据源的互斥只在入队时检查。任务被判为失联后，调度器会终止对应的工作进程；调度器与平台 PG 失联过久时，会终止全部工作进程。因此不会有两个同步同时写同一批原始层表。
- MySQL 的 `TIMESTAMP` 列在 DuckDB 里是带时区的时间，发往源端的水位线带 `+00` 后缀，要求 MySQL 8.0.19 及以上，由它按会话时区换算。
- 没有主键的表（如对象存储上的文件）分不清新增与更新，增量行一律记为新增，由映射声明的去重键在标准层合并。
- 判断新增还是更新时，要扫一遍这张表在原始层里的主键，开销随历史增长。以后可以改为对照标准层或全量比对的当前镜像。
- 读到的变化先放进内存里的临时表，再写进湖里。单个批次过大时可能超出内存上限；与 ADR-0010 一样，以后为工作进程提供本机临时目录供 DuckDB 溢写。
- 同步历史存在任务结果里，只列出最近 50 次同步。完整记录在数据湖的 `_batches` 里。

## Considered Options

- 数据源与数据湖各开一个 DuckDB，在进程内用 Arrow 搬数据：隔离更直观，但要自己分批搬运，大表时更复杂。不采用。
- 水位线存进平台 PG：页面读起来方便，但与湖里的数据不在同一个事务里。任务写完湖、没来得及记下结果时，会重复或漏掉一个批次。不采用。
