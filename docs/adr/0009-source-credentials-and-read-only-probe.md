# 数据源凭据信封加密，登记时由平台进程探测只读

数据源的凭据来自租户，泄露后影响的是租户自己的生产库，因此不沿用 ADR-0008 里“平台库访问权限即信任的根”的做法（租户数据库角色与对象存储账号的密码明文存放）。数据源凭据改用信封加密：每个租户一把随机的数据密钥，用它以 AES-256-GCM 加密凭据；数据密钥用平台主密钥 `PLATFORM_MASTER_KEY` 包裹后存在 `platform.tenant_keys`。密文绑定到租户与数据源（附加认证数据），换到别的租户或数据源上解不开。以后接 KMS 时只替换包裹与解包数据密钥这一步。模型服务的 API Key 也用同一套。

任务派发时由调度器解密，经 IPC 交给工作进程，以临时 secret 注入内存中的 DuckDB，不写进任务记录，也不落盘。工作进程拿不到主密钥。

平台“永不写入数据源”由三层保证：
- 登记与修改时探测账号的写权限，可写即拒绝，并列出可写的对象。采集任务运行时再探测一次。
  - PostgreSQL：查超级用户、建库与建 schema 权限，以及各表的 INSERT、UPDATE、DELETE、TRUNCATE。
  - MySQL：查各级写类权限。账号有可用的角色时，一律视为无法确认只读，因为经角色获得的权限不在权限表里。
  - 对象存储：对一个不存在的随机键发起分段上传并立即取消，再删除这个键。不写入任何数据，也不碰已有的对象。
  - 本机 DuckDB 文件：没有账号，只做只读挂载。
- 同时探测读权限。PostgreSQL 的目录里看得到没有读权限的表（缺 schema USAGE 或表 SELECT），只列表不读数会让测试连接通过、采集却失败。因此一张表都读不了时拒绝登记并给出授权语句；部分表读不了时照常登记，测试连接与数据源页列出这些表，采集跳过它们。
- 源端只读挂载，挂载后锁住 DuckDB 配置，此后不能再挂载其他库、读其他路径。PostgreSQL 的只读挂载把所有语句都放在只读事务里。
- 发往源端的只有平台写死的只读查询。成员和模型都不能给出发往源端的 SQL。

## 已接受的取舍

- 登记、修改与测试连接在 Web 平台进程里连接数据源，没有放进独立的工作进程：成员需要同步得到结果。这偏离了 ADR-0001“按任务独立进程”的精神。挂载同样锁定配置，资源上限较小（256 MiB、1 线程）。
- 平台进程会按成员填写的主机和对象存储地址发起连接，因此可以被用来探测平台所在网络（SSRF）。连接失败时，数据库驱动的报错会展示给成员；对象存储的失败只给出状态码与错误码，不回显响应内容。本期不限制可连接的地址，需要时在部署层面用出站网络策略加以限制。
- 本机 DuckDB 文件只能放在 `PLATFORM_SOURCE_FILES_DIR/<租户 ID>/` 下。每次连接前重新解析真实路径并校验仍在该目录内，登记后被换成指向目录外的符号链接时拒绝连接。校验与挂载之间仍有很短的时间窗。这个文件在锁定配置之前就被挂载（锁定之后无法挂载）。
- 文本列的列统计只给长度范围与格式特征，不给取值范围，因为取值可能是手机号等敏感信息。数值与时间列给出取值范围。列统计以后还要发给模型服务（spec：默认只发送表结构与列统计），这样处理可以避免敏感取值离开平台。
- 更新时间候选按列名识别（时间类型、命名像更新时间、样本中没有空值）。命名不常规的更新时间字段不会被识别为候选。
- 表清单、列统计与同步方式由登记后自动提交的采集任务产出，同步方式（含“无水位线的大表默认每天全量比对”）要在任务完成后才出现在数据源页上，不在登记请求的答复里：统计行数与列统计可能很慢，不适合放在同步请求里做。
- 丢失主密钥后，已保存的凭据无法解密，只能由成员重新填写。
