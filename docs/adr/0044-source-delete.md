# 删除数据源：前置条件、软删与清理范围

以前数据源只能登记、修改，不能删掉；目录版本里的「数据源删除」（ADR-0041）也因此一直没法产生。删除牵涉映射（ADR-0015、ADR-0031）、跨源引用（ADR-0030）、正在跑的任务与数据湖里的原始层，方案于 2026-10-27 确认（#283）。

- **前置条件**：同时满足才能删除，否则拒绝并列出全部原因（`deleteBlockers`）。
  - 数据源下所有映射都已停用，或从没发布过。已发布的映射先走双人停用（ADR-0031）。
  - 没有别的数据源跨源引用它（`crossSourceReferrers`，ADR-0030）。
  - 没有排队中或运行中的源任务（采集、同步、核对、业务主键检查），也没有待合并的任务。
- 删除依次锁源表行（与修改同步范围、恢复映射同序）、数据源行（与入队同步、核对同一把锁）、租户行（与发布、停用、入队合并互斥）。入队采集与业务主键检查不锁数据源行，可能在检查之后插进来；这样的任务派发时 `requireSource` 找不到数据源，任务失败，不写任何东西，因此不另加锁。
- **权限**：有 `publish` 权限的成员可以删除，不另设双人确认，因为前置的停用已经是双人确认。
- **只软删**：`sources` 打上删除标记（`deleted_at`、`deleted_by_email`），不删行。`source_tables`、`mappings`、`source_views`、`mapping_generations` 都对 `sources` 设了级联删除，删行会连同已停用映射的历史一起抹掉。已删除的数据源在 `requireSource`、`sourceIdByName`、`listSources` 里都查不到；名称的唯一索引只管没删除的行，可以重新登记同名的数据源。
- **平台库里删掉的**：凭据密文（`credentials` 非空列，写成空串）、同步范围（`source_tables`），以及没发布过的映射与映射草稿、没发布过的源视图与源视图草稿。先丢映射再丢源视图：`mappings.source_view_id` 没有级联。
- **平台库里保留的**：已停用的映射与已发布版本、已发布的源视图版本，以及数据源记录本身。
- **数据湖**：入队一个任务删掉原始层（`bronze_<id>`、`_keys`、`_mirror` 三个 schema）。标准层里已经合并进去的行保留，与停用映射一致。
- **审计与目录**：记审计 `source.deleted`（detail 为 `{ name, kind }`，不记凭据），并产生一个目录版本；变更记录里这个数据源和它的源表显示为删除。

另记两笔：

- 将来文件上传数据源（ADR-0037）删除时，数据湖前缀下的 `_uploads/<上传目录 ID>/` 也要一并删掉。
- 本机 DuckDB 文件数据源指向的文件不归平台管，删除数据源时不删它。

## Considered Options

- 硬删 `sources` 行：级联会删掉已停用映射与已发布版本，审计与目录里引用的历史对不上，否决。
- 删除也走双人确认：前置条件已经要求映射走完双人停用，再加一道只是多一步，否决。
- 有已发布映射时一并自动停用：绕过了停用的双人确认，否决。
