# 语义目录：按元数据实时生成，结构变化才记版本

AI 按需求起草映射、指标、标签与查询时，需要知道本租户有哪些数据、字段是什么口径、平台能算什么。原先每次起草临时拼一份很窄的上下文（指标只有实体、字段与关系，标签只有指标），没有业务口径、血缘、统计与平台能力说明，所以起草经常不准。决定：建一份**语义目录**，平台内的 AI 助手、单次起草与平台外的 Agent 共用。

**实时生成，不存成文档。** 目录每次按当前元数据（已发布的映射、自定义实体、合并组、源视图、同步范围、定义、业务说明）确定性地生成，可以渲染成 Markdown 或 JSON。不是在变更时写一份 Markdown 存起来：存下来的文档会比元数据旧，AI 会照着过期的结构起草。

**版本只记结构与含义的变化。** 映射发布 / 停用、自定义实体 / 合并组 / 源视图发布、同步范围与数据源增删、源表结构变化（ADR-0034）、定义发布、业务说明修改、平台能力变化，产生新的目录版本，同时存下与上一版的差异作为变更记录；外部 Agent 用版本号判断缓存是否过期。统计（行数、时间范围、常见取值）每次同步都会变，不产生版本，随条目返回并带上统计截至时间。

**总览 + 按标识展开 + 搜索。** 总览控制在约 4k token 以内，每项带稳定标识（只用名字、不带版本）；字段、取值、血缘、DSL 语法等细节按标识展开，也可以按关键词搜索条目。同步范围内还没映射的源表也收进来并标明「未映射」，同步范围外的不收（ADR-0013）。

**只给聚合，不给明细。** 统计只有行数、时间范围、空值率，以及按 ADR-0016 判定的低基数非敏感列的常见取值；敏感字段与哈希列不进目录（ADR-0005）。

**能力说明从代码生成。** DSL 的度量、运算、跳数与维度上限、模板与模板产出，都从代码注册表（`AGGS`、`FILTER_OPS`、`METRIC_SCHEMA`、`TEMPLATES` 等）生成，再配上手写示例，示例要在测试里通过校验，这样说明不会和代码漂移。

## Consequences

- 精准度用需求黄金集回归评估（评测命令），线上看草稿一次过校验的比例与发布前的改动量。
- 外部接口「指标与标签目录」（`/api/v1/catalog`）是语义目录的子集，保留原名。
