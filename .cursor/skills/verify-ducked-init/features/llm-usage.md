# 模型调用

An admin opens 模型调用 and sees this tenant's model calls for the last 7 or 30 days. The page groups them by purpose and shows calls, input and output tokens, average and P95 duration, schema pass rate, and error rate. A totals row is its own aggregate. The detail list is 50 rows per page, newest first. A data engineer, an analyst, and a viewer get HTTP 403 and have no nav entry. Another tenant's rows never appear. 测试连通性 on 模型服务 writes a row that then shows up here, including a failed call to an unreachable endpoint.

## Sub-features

- `llm-usage-empty` shows the empty state before any `llm_calls` row exists.
- `llm-usage-nav` shows 模型调用 immediately after 模型服务 for an admin, and hides both links from the other three roles.
- `llm-usage-forbidden` returns 403 with 无权访问 and 仅管理员可以配置模型服务 for a data engineer, an analyst, and a viewer. A signed-out GET redirects to `/login`.
- `llm-usage-stats` matches `platform.llm_calls` for calls, tokens, average duration, P95, schema pass rate, and errors. The totals row is not the average of the per-purpose P95 values. A purpose whose `schema_valid` values are all null shows 「—」.
- `llm-usage-window` follows `?days=7` and `?days=30`. Any other `days` value, including `99`, `0`, and a value that looks like SQL, uses the 7-day window. Rows 10 days old appear only on 30. Rows 40 days old appear on neither. The other tenant's rows appear on neither.
- `llm-usage-page` lists 50 rows per page, `created_at` desc then `id` desc. `?page=2` is the next page. `?page=0`, a negative page, a non-numeric page, and a page past the end clamp to 1..pages. A failed call is red, the visible error is at most 120 characters plus 「…」, and the `title` attribute is the full error.
- `llm-usage-connectivity` runs 测试连通性 against the local stub and then shows a `connectivity` row for `platform-default`. Saving an unreachable endpoint and testing again shows a failed `connectivity` row whose error does not contain the API key.
- `llm-usage-isolation` shows a second tenant's admin only that tenant's row.

## How to get to it (user POV)

- Choose `模型调用` in the top nav. The path is `/llm-usage`. The link sits immediately after `模型服务`. Admins see both. Other roles see neither.
- The page heading is `模型调用`. The title is `模型调用 · CRM 数据分析平台`.
- The empty state links to `模型服务`. That is `/model-provider`.
- `近 7 天` goes to `/llm-usage?days=7`. `近 30 天` goes to `/llm-usage?days=30`.

## Gotchas

- `wait-text` is exact. `暂无模型调用` does not match the empty-state element, because that element's text continues through the `模型服务` link. `admin@verify.test（管理员）` does not match either. The home line's element text is `当前租户 · 默认空间 · admin@verify.test（管理员）`. `近 30 天本租户的模型调用` is a prefix of the description, not the whole text node. Wait for a full cell such as `67 / 33` or the heading `按用途统计`.
- `count --selector` takes a raw CSS selector. Pass `a[href="/llm-usage"]`. A selector that still contains backslashes is invalid.
- `?days=99` stays in the address bar. The fallback is the numbers, which match 7 days. `?page=9` stays in the address bar and the pager reads `第 2 / 2 页`.
- The totals P95 is a second query without `GROUP BY`. Averaging the purpose P95 cells does not equal it.
- Schema pass rate uses only rows where `schema_valid` is not null. All-null, which is what `embedding` and a failed fetch store, renders 「—」.
- Token and duration text uses `zh-CN` grouping, so 99999 renders as `99,999` and 5000 ms renders as `5,000 ms`.
- 测试连通性 writes `connectivity` and, when the stub answers the ping tool, `tool_probe`. Compare the connectivity row with the earlier count before calling the click a single new row of that purpose.
- `sql-write.sh` connects only to `crm_platform_verify_<run-id>`. `postgres` and `crm_platform` are refused before any statement runs. Do not use it to insert members, sessions, or audit rows. Invite the three roles from the members page.
- `pnpm tenant:create` reads `PLATFORM_DATABASE_URL`. Source this run's `app.env` first. Do not copy `PLATFORM_MASTER_KEY` or the stub key into the evidence directory or this file.
- An unreachable `127.0.0.1:9` fails at once with `fetch failed`. A black-hole address waits for the 60-second model timeout. Use the closed port.
- Both usage queries bind `tenant_id` and `days` (`$1`, `$2`). `page` becomes `limit` / `offset` parameters. A `days` or `page` value that contains SQL does not run as a statement.
